# 测试版 API2API 与财务原型

这两个功能只在 `MAILAPI_MODE=test` 下注册，数据写入测试数据目录中的

## API2API

管理员通过“连接设置”弹窗配置独立 NewAPI 的 `/v1` 地址和管理凭据；上游中转站地址与 API Key
通过“添加渠道”提交给网关。测试版要求独立的测试凭据密钥，网站侧管理和关联凭据以现有
AES-GCM 密钥封装。网站用户创建自己的原生 API Key，创建时展示完整内容，之后可按需复制；
本站密钥记录只保存哈希、前缀和网关关联编号，独立网关的令牌存储边界见下文。

用户客户端使用下面的地址调用：

```text
Base URL: https://网站地址/api2api/v1
Authorization: Bearer <网站生成的 API Key>
```

请求会异步转发到 NewAPI，使用共享连接池，最多保留 200 个并发连接。非流式响应从 `usage` 读取输入、输出和总 Token，流式响应会解析 SSE 中的 usage 片段。每个网站 API Key 关联网站账户，SQLite WAL 表记录用户、模型、状态码、耗时和 Token 汇总。早期 legacy 原型仅统计 Token；现已停止通过网站签发旧模式密钥或使用共享上游转发，原有数据保留供历史查询。当前由原生网关管理额度。

NewAPI 本身提供 OpenAI 兼容接口、API Key、模型组和用量日志，适合作为上游网关。[NewAPI README](https://github.com/unorouter/new-api/blob/main/README.en.md)、[API Key 文档](https://github.com/QuantumNous/new-api-docs-v1/blob/main/content/docs/en/guide/feature-guide/user/token.mdx)、[Token 用量接口](https://github.com/QuantumNous/new-api-docs/blob/main/docs/api/token-usage.md)

### NewAPI 引擎接入验证

测试版固定使用 NewAPI 原生密钥（newapi），界面和 HTTP 配置接口不再提供模式切换。配置请求省略 `engine` 时仍按原生网关处理，显式选择 legacy 会被拒绝；用户签发、启停和模型转发也不再回退到旧共享模式。底层保留旧格式的读取及历史数据，不自动迁移或把旧上游地址当作独立网关。BaseURL 保持 `/api2api/v1`；旧模式或其他网关的密钥不能调用当前入口。正式版不加载这些路由。

原生模式下，网站为每个账户关联独立的 NewAPI 普通用户（role 1），用随机服务凭据关联，不传递网站密码、会话或二次验证码。服务凭据和独立网关管理凭据由测试密钥加密存储，JWT/轮换刷新令牌只缓存在进程内。NewAPI 签发 `sk-` 密钥，网站仅保存哈希、前缀和关联编号。创建时展示完整值，之后用户可在列表点击复制：后端以该用户独立网关身份调用原生 Key 读取接口，核对哈希后返回，响应禁止缓存，不把明文补写入本站数据库或浏览器存储。旧共享模式 Key 只有哈希，无法再次读取；需要时创建新的网关密钥。停用先阻断本站鉴权，再同步原生令牌状态；启用须先确认网关恢复成功，再允许本站调用，沿用原 Key。临时停用与永久撤销通过独立 `revoked` 标记区分；旧版已停用记录原本表示撤销，升级时保留为永久撤销，不能通过启用恢复。同步失败会报告并保留阻断状态。撤销先停用本站哈希，再撤销 NewAPI 令牌；远端暂不可用时本站立即阻断，并提示重试远端撤销。

NewAPI 独立保存上游渠道、原生令牌及权威额度；本站保存补充的每次调用耗时、状态码和 usage，不重复扣费。初始额度默认 0；管理员可设新用户初始额度或调整个人剩余额度，单位为 NewAPI quota 点数，不解释为人民币或实际付款。当前网关统计聚合有刷新延迟（该验证版本默认约 5 分钟）。

模型调用不经过 NewAPI 管理 API：本站查密钥哈希及当前账户状态后，使用原生密钥通过连接池转发原请求字节，禁止跳出 `/v1` 路径，转发中不注入提示词、不替换模型名、不重试生成请求。SSE 随收到的数据块交付，本站不等待整段完成；NewAPI 本身的处理仍可能增加开销。该实现增加一次本站转发跳数，尚未对真实上游测量首 Token 延迟、吞吐或生成质量。

重要存储边界：此处加密的是网站侧管理和服务凭据。验证版本 NewAPI 自己的数据库保存可用原生令牌值，不能声称整个系统只存哈希。独立数据库、日志与备份须按敏感凭据管理，限制文件权限和网络访问。当前测试网关仅绑定回环地址，管理连接与远端上游要求 HTTPS（本机回环验证除外）。上游凭据只发送给 NewAPI，不在网站渠道列表返回。

`scripts/verify_newapi_engine.py` 使用官方 macOS arm64 `v1.0.0-rc.51` 发行文件，并在执行前校验固定 SHA-256。它仅在回环地址启动网关和本地确定性上游，创建独立临时数据库及随机测试管理员，启动仅用于验证的隔离网站，验证独立用户、原生密钥、本站 HTTP 入口、普通请求参数和响应内容、额度/渠道查询，以及响应结束前的流式交付、撤销和跨用户权限。退出时关闭服务并清理临时数据库；不访问网站运行数据，不连接真实模型或进行真实计费。该检查不代表真实上游的性能或生成质量基准，测试发行候选版也不自动成为正式部署版本。

本地验证命令（先自行下载官方发行文件）：

```bash
uv run --offline --python .venv/bin/python python scripts/verify_newapi_engine.py \
  --binary /path/to/new-api-macos-v1.0.0-rc.51
```

### 测试版 API 工作台

本站保留原有顶栏、侧栏、主题和页面缓存，API 工作台按 NewAPI 的信息结构重新组织，未引入其整套 React 界面或复制源码组件：

- 用量总览：本站累计请求和 Token、最近 100 次的完整请求平均耗时、NewAPI 剩余额度、最近 30 天网关聚合趋势、可用模型、BaseURL 复制和 curl 示例。完整耗时包含模型生成时间，不作为首 Token 延迟。
- API 密钥：保留名称/前缀、状态和已用额度；补齐模型限制、调用者 IP 白名单、创建/最后使用时间和过期时间。操作使用启停、编辑和更多三个图标，复制与永久撤销放在更多菜单。模型/有效期编辑使用独立普通用户身份及版本校验，不改密钥本身、额度或启停状态；清空模型限制仍保留网站全局模型范围。IP 白名单按 NewAPI 的输入方式设计：每行一个 IPv4、IPv6 地址或 CIDR 网段，留空不限制，最多 100 条；列表显示规则数量，悬停可看完整内容，编辑弹窗可查看和修改。本站按调用者 IP 执行规则，原生网关的连接 IP 规则保持独立且不覆盖。关闭弹窗或离开页面会清除可见明文；剪贴板不可用时提供临时手动复制弹窗，延迟返回的复制请求不能在已离开的页面展示密钥。创建期间关闭窗口时，不展示迟到的密钥，尝试撤销未领取密钥；失败时提示去列表撤销。远端撤销失败可重试。
- 使用日志：按日期、模型、分组、类型、个人令牌及请求 ID 筛选，支持每页 20/50/100 条及全部历史翻页；时间、令牌/分组、模型、流式、输入/输出 Token、费用、耗时/首响和详情按照参考站组织。支持隐藏列以及全部匹配记录的 CSV/JSONL 导出。费用读取原生已扣 quota 和网关显示换算，缺少换算时显示配额点；不从 Token 数估算金额。首响只显示网关提供的有效测量值，整数秒耗时导出的 t/s 仅为近似输出速度。请求 ID 精确筛选下不适用原生统计接口，明确显示当前页用量，RPM/TPM 留空。
- 模型广场：所有登录用户可搜索并查看本人权限及网站允许范围内的实际模型。沿用七七 AI 的“筛选栏 + 卡片/表格 + 模型详情”结构，支持分组、供应商、标签、计费类型和端点组合筛选，按名称或价格排序，每页 20/50/100 条完整翻页，复制模型 ID。模型详情包含概览、性能和 API 三个页签，展示分组价格、实际性能图表、可用端点及本站 Base URL 的 cURL/Python/JavaScript/TypeScript 示例。首次访问以 POST 创建独立普通用户关联，沿用现有初始额度策略，不自动签发 API Key。
- 审计日志：仅管理员（含普通管理员）可见，后端独立校验权限。记录创建、读取、启用、停用、编辑限制和撤销的操作者、所属用户、密钥元数据、时间及结果；持久化操作意图后执行远端调用，分别标记成功、失败、待核实或处理中。支持日期/关键词/事件/结果筛选及完整分页。从本次更新开始记账，不补造历史事件；不记录完整 Key、哈希、管理凭据或请求正文。
- 网关管理：管理员先查看连接摘要、上游渠道和用户用量；通过“连接设置”弹窗保存连接和独立管理凭据，验证连接、添加 OpenAI 兼容渠道、覆盖个人剩余额度。当前只支持添加渠道；高级路由、编辑、删除由独立 NewAPI 管理。普通用户不展示管理入口，后端仍独立验证权限。

测试版各功能页主标题统一为财务中心的 21px、600 字重及页面内缩，移除主标题上下说明文字，保留功能模块内部标题。资源页新增目录上方的“资源”标题；目录滚动后仍固定在全站顶栏下。生产资源模板未改动，标题由测试版页面处理器添加。API 页将引擎名称统一显示为“网关”，内部 `newapi` 协议标识、密钥命名空间及独立引擎本身不变。

API 页面沿用财务页的页签、按钮、筛选框箭头、字号层级、卡片间距、表格行距及顶部弹窗布局，图标采用同一套线条样式，动画遵循减少动态效果偏好。密钥表移除单一网关下重复的来源列，名称/前缀搜索与状态筛选组合使用；管理员用户表支持账户和备注搜索。筛选仅影响当前表格，累计调用量不变。连接摘要中的“已启用”只表示已保存的开关状态，实际连通性通过“验证连接”单独检查。

新增字段和功能覆盖简体中文、English，以及现有外观主题和窄屏布局。所有表格中的用户文本按纯文本处理。

模型目录仅使用独立普通用户身份读取原生 `/api/user/models`、`/api/user/self/groups`、`/api/pricing`、`/api/status` 和近 24 小时性能汇总，返回前再次限制网站模型范围与可用分组，供应商、标签、描述和端点均取真实元数据，不按模型名前缀猜测。只展示本站 `/api2api/v1` 能转发的端点根路径，不把网关自己的 `/v1beta` 当作本站接口。额外诊断、凭据、隐藏模型及分组数据不透传；元数据查询失败时仍保留实际可用的模型 ID，缺失价格/性能显示为 `—`。

模型按量基础价按原生比例换算为 USD / 1M Token，分组乘以该用户实际可用的分组倍率；全部分组视图使用最低已知分组价格，所选分组视图使用对应价格，`/1K` 只改变展示单位。按次费用不随 Token 单位变化。标准/充值切换仅使用网关提供的显示汇率及充值折算率，缺少有效折算时禁用充值选项，不改计费配置或余额。动态表达式和插件计费不被当作固定价或免费，也不在浏览器执行表达式；当前说明按实际请求结算，完整动态分档报价尚未移植。

模型性能是网关提供的站点聚合，独立于用户自己的使用日志；不以卡片数或客户端平均值推算成功率、首响和吞吐。详情按需加载，后端再次校验模型权限并移除不可用分组，只按真实时间桶绘图，只有一个时段时显示该时段数值并提示继续积累样本，不生成虚假趋势；未测得的首 Token 延迟显示为 `—`。过期请求不能覆盖新弹窗。卡片状态条只显示所选 24 小时窗口内有样本的原生时间桶。API 示例始终使用本站地址、模型 ID 和 `API_KEY` 环境变量占位，不读取用户明文密钥，也不会自动发起计费调用；目前提供 Chat、Responses 和 Embeddings 的完整请求示例，其他端点显示真实方法与地址并提示按相应协议构造请求体。

IP 规则保存在测试数据库的 `api2api_keys.caller_ip_allowlist`，旧密钥迁移为空白白名单，不改变原有效性；网段规范化并去重，IPv4 映射 IPv6 地址按 IPv4 判断。保存时把本地规则纳入版本校验，并在远端模型/有效期修改成功后使用本地条件更新，失败不放宽旧规则。编辑 IP 不重新签发 Key，不修改额度、启停状态或原生 `allow_ips`。修改记入现有“编辑限制”审计事件。

转发入口在读取请求正文和连接上游前检查白名单，未匹配、来源无效或已存规则损坏时返回 OpenAI 风格的 403 `ip_not_allowed`。只使用 `request.client.host`，不自行信任 `X-Forwarded-For`、`X-Real-IP`、`Forwarded`；沿用既有可信反代边界，不新增可信代理或更改正式入口。测试版继续仅绑定回环并关闭 Uvicorn 自动代理头处理，因此本机调用看到 `127.0.0.1`/`::1`，需远程部署时另行验证代理确实传递真实来源。白名单修改作用于之后发起的请求，不中断已进入转发的请求。规则解析缓存有容量上限，模型调用不增加网关管理请求。未启用 IP 白名单的密钥继续按原流程处理。

使用日志通过服务端管理身份查询原生历史接口，查询用户名固定为当前网站用户的独立网关映射，不接受客户端提供用户名或用户 ID；返回前逐条复核原生用户编号及用户名，任一不符则整页拒绝。个人密钥筛选也先校验归属，其他用户的令牌无法查询、复制、编辑或启停。管理身份不发送到浏览器。只返回经过白名单处理的调用与计费元数据，不返回原生 `content`/诊断字段或完整提示词、回复。日志可浏览网关仍保留的全部历史，但不能恢复网关已清除的数据。本站原有调用汇总及 legacy 历史继续保留，未自动混入原生使用日志或删除。

导出在私有测试目录生成临时文件，完整成功后再响应，传完删除；失败、取消或翻页期间检测到数量/顺序变化时丢弃文件并要求重试。同一用户每次只执行一个导出，CSV 防止公式执行。真实引擎验证包含 145 条早于普通用户查询窗口的隔离日志、跨用户拒绝、模型目录、密钥编辑和审计；前端测试包含分页、迟到响应、错误清空、角色降级及导出失败行为。

验证预览使用独立、仅回环可访问的 NewAPI 和明确标注的确定性模拟上游，模拟返回的 Token 仅供功能验证。监督进程拥有网站、网关、上游、临时测试数据与独立加密密钥：停止网站或监督进程后，会结束相关子进程并删除整套临时目录。显式 `TEST_DATA_DIR` 的常规启动规则仍然保留原目录；不要把监督预览的清理行为描述为所有显式目录都会自动删除。原网站临时快照的自动清理规则不变。正式服务和正式数据库结构不受影响。

## 财务申请

用户在测试版页面提交报销申请。项目和金额必填，项目最多 20 个字符，发票必须上传，支付记录截图可选。允许 PDF、JPG、PNG 和 WebP，单个文件不超过 10 MB。上传接口允许两个文件同时提交，文件名不设应用层长度截断。

“我的申请”始终只显示当前网站账户提交的申请，管理员也遵循此规则。待审核申请可修改或撤销；已驳回申请可以修改后重新提交，生成新版本并回到待审核。用户不能修改已通过及已撤销申请。驳回必须填写原因，编辑和审核携带版本号，旧页面的操作发生冲突时返回 409，不覆盖新版本。

账户备注和当前分组在读取、页面显示及普通下载时动态查询。费用归属另行保存：未分组账户记为“未分组”，单分组自动填写，多分组必须从本人所属分组选择一个。历史费用归属不随日后换组而改变，金额只计入一个费用组。已有申请迁移时只有一个历史组名的保留该名称，多分组但缺少费用归属信息的记为“待确认”，不猜测归属。

管理员（含普通管理员）使用“申请审核 / 统计分析 / 审批记录 / 公告管理 / 我的申请”五个页签。审核默认全部时间、待审核，统计默认本月；支持日、周、月、自定义范围，关键词、状态、费用组、付款人、审核人及金额筛选。审核历史使用审核时间，其他列表与金额统计使用提交时间。金额以整数分计算，申请总额排除已撤销项。通过仅表示审核通过，不表示付款。表格每页最多显示 25 行，图表在本地绘制，无外部图表加载依赖。

管理员可在“审批记录”中，对当前有效、资料版本未变化的已通过或已驳回记录点击“再审核”，改为相反结果。改审原因必填，仍为 500 字上限；记录改审人、时间及被替代审批编号（`finance_events.supersedes_event_id`），原审批及附件快照不覆盖。申请资料版本保持不变，新增审批事件；并发校验同时使用资料版本和最新事件编号，防止旧页面在结果多次切换后覆盖新审批。用户已修改重提、撤销或其他管理员已改审时返回 409，需刷新后操作。

历史列表标记“已被后续操作替代”，只有最新有效审批可再审核。日期分组保留全部审批动作，金额小计仅计当前有效通过记录，避免改审后的重复统计。批量下载仅接受当前仍有效的通过事件；混入任何旧通过事件时拒绝整批导出。旧记录和原附件仍可在详情中查看、单独下载。当前申请统计始终按每笔申请的最新状态计算，不按审批次数重复累计。

公告支持标题阅读、历史弹窗、发布、编辑、删除和置顶，与顶栏网站公告独立。用户文本及附件名按纯文本显示。

管理员可点击“申请审核”列表中申请行的文字或空白处打开详情，也可聚焦行后按 Enter / 空格。按钮、附件下载链接和其他交互控件仍执行各自操作。详情显示当前申请资料、发票及支付记录各自的缩略图和原有操作历史；点击缩略图复用 PhotoSwipe 放大、缩小，多页 PDF 可翻页。图片和最多 5 页的 PDF 在私有测试目录按需生成预览（长边最多 2400 像素），缓存后不重复渲染，不调用 OCR，不替换原附件；原文件仍可下载。预览与原附件遵循相同的本人/管理员权限，历史版本使用对应附件；无法预览时提示下载原文件，一种附件预览失败不影响另一种，关闭详情或离开页面会清除未完成的预览与大图状态。统一附件预览入口为 `attachment-preview?kind=invoice|payment`，原 `invoice-preview` 入口保留兼容。

发票和支付记录大图共用独立的全屏图层，首次完整适配屏幕并留出控制栏和阴影边距，点击图片切换缩放，点击图片外、关闭按钮或 Esc 返回原详情位置。管理员详情底部固定显示审核操作：待审核显示通过/驳回，当前有效的已通过/已驳回显示再审核，普通用户及已撤销申请不显示审批按钮。沿用已有意见、改审原因和版本校验，审核成功后刷新仍打开的详情及操作历史。

### 中国普通发票检查

新上传的发票在本机识别，PDF 优先提取文字，扫描 PDF 和图片使用随测试依赖安装的本地 OCR 模型，不上传第三方。自动填写票号、代码、开票日期、价税合计和可识别的校验码；用户核对、纠正并确认后提交。支持 20 位数电票号，以及 8 位票号配 10/12 位代码，票号与代码按文本保留前导零。单笔申请仍对应一张发票；识别出多张不同票号时要求拆分。PDF 最多识别 5 页，识别超时或无法识别时允许手动补全，页面提示识别结果不等于税务验真。

上传预识别与提交复用同一份服务端识别结果：按网站账户、服务端计算的文件 SHA-256、解析文件类型绑定，单个服务进程最多缓存 64 份结果，30 分钟过期。只缓存识别字段及提示，不保留预识别原文件，不跨账户共享；并发识别同一文件时复用已完成结果。识别失败允许重试，缓存失效、被淘汰、进程重启或请求落到其他进程时会重新识别。缓存不保存“是否重复报销”的结论，提交、修改重提、改审为通过仍在数据库事务中检查当前占用，用户纠正后的票面字段继续单独验证并保存。

发票号码（普通票同时使用代码）或完全相同的附件内容，被其他待审核、已通过申请占用时，阻止重复提交。申请被驳回或撤销后释放；修改重提、改审为通过时再次检查，数据库事务防止并发重复占用。查重提示不透露其他申请人信息。历史申请缺少票面信息时，已有附件可按内容查重，票号查重需先由管理员补录。

管理员在“发票检查与税务查验”中下载原发票、复制查验信息，并打开国家税务总局查验平台手工查验；回到本站登记通过、信息不一致、查无此票、作废或暂无法查验及说明。本站不自动调用税务平台、不代填验证码，也不把 OCR 当成验真结果。查验登记保存操作人、时间、资料版本、票面信息和附件版本，不改变审批结果。替换附件或修改票面字段会清除当前查验结论，旧登记和旧附件继续保留；并发登记需刷新后重试。用户只能查看本人发票及登记结果。

### 报表与站内通知

财务标题区“导出报表”提供 Excel 和 UTF-8 CSV。申请审核、我的申请导出当前筛选的全部匹配申请，审批记录导出全部匹配历史动作，统计分析导出费用分组统计。日期采用浏览器时区，审批记录按审批日期，其余按申请日期。普通用户仅能导出自己的报销明细；管理员“我的申请”也只导出本人申请。报销明细包含票号和税务查验登记，分组统计使用每笔申请当前状态，排除撤销，不重复累计改审记录。Excel 金额为数值，文本避免公式执行；临时导出文件响应结束后删除。

顶栏铃铛增加“报销通知”：新申请、修改重提通知管理员；审批和再审核结果通知申请人。点击可进入有权限查看的申请详情，各账户已读状态独立，支持分页浏览和全部已读。历史结果标明申请后续状态，避免把旧审批当成当前结果。

待审核满 7 天后，在线管理员轮询通知时生成待办提醒，同一申请至少间隔 24 小时再次提醒。修改重提重新计算等待时间，普通待审核编辑不重置计时；审核或撤销后停止提醒。当前实现仅站内铃铛，未接入邮件、短信或离线推送。

### 版本记录和附件下载

- `finance_applications` 保存当前状态、版本号、费用归属及当前资料；`finance_files` 关联当前附件。
- `finance_versions` 保存每个版本的申请和附件元数据快照；`finance_events` 追加记录提交、修改、重提、撤销、审核的操作者、时间及意见。应用接口不覆盖旧快照或删除历史事件。
- 替换附件保留旧物理文件，使旧版本仍可下载。历史附件暂不自动清理，随隔离测试目录整体清理。
- 单文件名为 `分组_用户名备注_报销项目_发票/支付记录.扩展名`，普通下载按当前账户信息命名。
- 审批记录只可勾选当前有效的已通过记录，最多一次 500 条，导出该次审核对应版本的发票和支付记录，并附 `审批清单.json`（版本、审核人、审核时间、金额、归属和意见）。历史导出按当时的申请身份命名，不用后来替换的文件。
- 缺失附件返回 410，整包取消，不静默生成不完整的压缩包。普通用户只能读取本人申请及其版本、附件；管理员可审核及查看全部记录。

以上均为测试版实现。申请、历史、公告写入隔离的 `test_features.sqlite3`，上传附件使用随机存储名和私有权限 `0600`，目录 `0700`。它们不复制回正式数据目录，也不改变正式版数据库结构。测试启动仍从当前本地正式数据创建临时快照；API2API 与财务没有正式对应数据，初始为空。验证或预览生成的数据仅保存在测试目录，正常退出时自动清除。

## 测试方式

测试版需要独立数据目录和测试密钥。API2API 配置要求同时启用测试 OAuth 加密：

```bash
TEST_DATA_DIR=/path/to/test-data \
TEST_CREDENTIAL_KEY_FILE=/path/to/test-key.json \
TEST_OAUTH_ENCRYPTION=1 \
TEST_SITE_ACCOUNTS_BACKEND=sqlite \
TEST_RESOURCE_BACKEND=sqlite \
TEST_EXTERNAL_WATCHERS=0 \
python code-receive-test.py
```

登录后打开 `/test-features`。测试进程退出后，临时测试目录按现有隔离规则清理。
